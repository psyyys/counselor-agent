# 咨询师 A（CBT 流派：CBT + DBT + ACT）设计 v0.1

> 2026-10-21。用户决定：**框架和结构直接采用 PsychEval**，不再自己设计。
> PsychEval 来源：华东师大 ECNU-ICALK，论文 arXiv 2601.01802，数据授权 CC BY-NC 4.0（非商业可用）。
> 下文凡标注「PsychEval」的，都是照搬对方的做法；标注「本项目改编」的，是因为对方是离线造数据，我们是实时对话，必须改动。

## 1. 和 PsychEval 的根本区别
| | PsychEval | 本项目 |
|---|---|---|
| 用途 | 评测基准 / 训练数据 | 实时对话的咨询师 Agent |
| 来访者 | 由案例报告驱动的模拟来访者 | 真人 |
| 计划从哪来 | 事先由完整案例报告生成 | 第 1 次会谈收集信息后生成，每次会谈后更新（本项目改编） |
| 让模型"专业"的方式 | 用数据训练或评测 | 不微调，在调用时约束：检索范例 + 技能库 + 督导审查 |

## 2. 疗程层（跨会谈）——PsychEval
- 共 5–10 次会谈，分三个阶段：**问题概念化与目标设定 → 核心认知与行为干预 → 巩固与复发预防**
- 第 1 次会谈必须完成完整的初始评估（PsychEval E.2）
- 每次会谈结束时评估进展，决定进入下一阶段还是继续巩固当前阶段（PsychEval Phase 3）
- 每次会谈用 `theory_select` 字段从 CBT / DBT / ACT 中选一个疗法（PsychEval 整合型案例的做法）。三个疗法都属于 CBT 家族，不涉及其他流派

## 3. 会谈层（每次会谈开始和结束时调用，不是每轮都调用）
**开始时**
1. 读取长期记忆，生成本次会谈的议程（PsychEval E.4）：已知的信息用"回顾"的方式提问，未知的用"探索"的方式提问；上次没完成的目标顺延到本次
2. 按当前阶段和本次议程，从技能库中挑选候选技能（PsychEval E.5）

**结束时**
3. 写会谈总结（PsychEval E.9）：约 500 字摘要、目标完成情况、来访者状态、作业
4. 提取本次会谈新获得的来访者事实（PsychEval E.7）：区分事实和愿望，区分核心信念和一时的情绪
5. 把新事实合并进个案档案（PsychEval E.8）：去重；遇到矛盾时不直接覆盖

## 4. 每轮对话：约 2 次调用
```
用户消息
 → 安全预检（代码匹配关键词，不调用模型）── 命中 → 固定危机流程
 → 检索：PsychEval CBT 对话中相似的咨询师片段（附带 <think>）＋ 技能卡片（＋ 手册片段）
 → 【调用1 主模型】先输出 <think>（评估 / 来访者状态 / 技能，最多 2 个 / 策略 / 风险），再输出回复
 → 【调用2 督导模型，用便宜的型号】按清单审查 ── 不通过 → 重写一次（偶尔会多出这第 3 次调用）
 → 回复显示给用户；<think> 内容只显示在网页右侧的检查面板
```
主回复的规则直接采用 PsychEval E.6：
- 每句回复最多问一个问题
- 每轮最多用两个技能
- 结束会谈时做总结、布置作业，最后一句不是问句

督导的审查清单：以 CTRS 条目（PsychEval 评测提示词 `prompts_cn/ctrs`）为基础，再加本项目的硬性规则：
- 不做诊断
- 不做精神分析式的解释
- 不超出 CBT 家族
- 符合当前会谈阶段和议程

## 5. 长期记忆（本地 JSON 文件）——格式采用 PsychEval
- `profile.json`：个案档案。CBT 字段包括：核心信念，以及特殊情境链"事件 → 条件假设 → 补偿策略 → 自动思维 → 认知模式"（认知模式从 15 种认知歪曲里选）
- `plan.json`：三阶段疗程计划，以及当前所在阶段
- `sessions/NN.json`：每次会谈的总结、目标完成情况、作业，以及下次会谈时回顾作业的结果
- 在网页上可以查看和修改

## 6. 范例库与知识库
| 库 | 内容 | 状态 |
|---|---|---|
| 范例库 | PsychEval CBT：148 个案例、约 1000 次会谈、约 2.5 万句带 `<think>` 的咨询师发言 | ✅ 已下载到 `third_party/PsychEval/data/cbt` |
| 技能库 | 从上述数据中汇总出的 CBT 微技能，共 1174 个（含"何时使用"和"触发条件"；PsychEval 依据 Beck《CBT: Basics and Beyond》第 3 版整理） | ✅ 可以直接抽取 |
| 手册库·CBT | VA CBT-D 治疗师手册（227 页）、VA CBT-D 策略指南、VA CBT-CP 慢性疼痛治疗师手册 | ✅ 已下载，文字可以提取 |
| 手册库·ACT | Harris《ACT Made Simple》Extra Bits（只有 7 页，基本是链接）；WHO《压力之下做要事》中文版（基于 ACT） | ⚠️ WHO 网站连不上，需要用户手动下载 |
| 手册库·DBT | 没有合法的免费手册（Linehan 的手册是 Guilford 出版的付费书） | ❌ 需要用户提供 |

## 7. DBT / ACT 范例的生成（第二期）——按 PsychEval 的方法
1. 技能库：用 GPT 类强模型从 DBT、ACT 手册中解析出元技能和微技能，格式与 PsychEval 一致（需要先有手册）
2. 案例来源：公开发表的 DBT/ACT 案例报告（PubMed Central 上的开放获取案例等），用 E.1 的方法抽取成个案档案
3. 生成：E.2 疗程计划 → E.4 会谈议程 → E.5 技能选择 → E.6 同时扮演咨询师和来访者生成对话 → E.9 会谈总结
4. 质控：用户抽查；数据打上 `source: synthetic` 标签，单独建索引；做实验时可以开关这部分范例

## 8. 评测——直接使用 PsychEval 的评测框架
`third_party/PsychEval/eval`：包括模拟来访者、督导打分和中文提示词（CTRS、WAI、SRS、SCL-90 等）。对比两组：
- 只加一句提示词的千问
- 咨询师 A（千问 + 本项目的全部约束）

## 9. 技术栈
- Python 后端（FastAPI）+ 一个 HTML 页面；双击 `启动.bat` 运行
- 主模型：千问（qwen-plus 或 qwen-max）；督导：qwen-flash/turbo。按 OpenAI 兼容接口写，换模型只需要改配置
- 检索用的向量模型：待定（本地 bge-small-zh 免费但要装 torch；或用千问的 embedding API，费用很低）

## 9d. v0.3 语音通话（2026-10-28）
- 用户决定：识别 qwen-audio-3.0-asr-flash、朗读 qwen-audio-3.0-tts-plus；保留督导 + 等待提示；允许打断
- 采用"识别 → 咨询师 A 原流程 → 朗读"的串联方式；不用端到端实时语音模型（会绕过议程/督导/记忆等约束）
- 两个语音模型都走百炼原生接口（`counselor/voice.py`）；识别要用 `input_audio` + `parameters.format`，OpenAI 兼容接口会 400
- 浏览器端：录音直接编码 16kHz 单声道 wav，按音量判断说话开始/结束（静音 1.1 秒算说完），咨询师说话时检测到明显人声就停播（打断）
- 危机：屏幕显示热线卡片，同时朗读简短版热线
- 未在真实麦克风上测过（浏览器面板不能用麦克风）；朗读→编码→识别整条链已在页面里验证

## 9f. v0.5 长段说话与声音（2026-10-28）
- 问题：语音通话里说满 45 秒会被强制发送（代码里的上限），来访者常常一讲几分钟
- 修复：取消总时长上限；说满 40 秒后在换气停顿处（≥0.22 秒）切一段先送识别，最长 60 秒强制切，各段按顺序拼接；模拟测试 3 分钟连续说话 184.6 秒全部保留
- 新增「我说完了」按钮；设置「由我决定什么时候说完」（手动模式：停顿多久都不接话）；说话超过 8 秒显示"我在听，你慢慢说 · 已经说了 m:ss"
- 声音：用户觉得灵心偏年轻。Token Plan 实测只开通 qwen-audio-3.0-tts-plus（3.1-flash、3.0-flash、CosyVoice、声音设计 voice-enrollment 都返回"模型不存在"），所以新增「声音风格」：原来 / 成熟沉稳（默认）/ 温厚长辈 / 低柔安静，用朗读指令调；试听样本在 `web/voice_samples/`
- 若以后换成普通百炼 API Key，可用 qwen-audio-3.1-tts-flash 的成熟女声（许玉远、闻怀之、顾云舒、谢舒柔等）或"声音设计"自定义音色

## 9h. v0.7 声音线索（2026-11-02，本项目改编）
- 识别模型（qwen-audio-3.0-asr-flash）不返回情绪，但返回逐词起止时间；浏览器录音能测音量。由此算出：语速（字/秒）、超过 1 秒的停顿次数与最长停顿、说话时长、音量
- **只和来访者自己比**：用本次通话前面句子的平均值做基准（前两句只建立基准，不提示）。阈值：语速 ±25%、音量 −30%/+40%、时长不到平时 35%
- 有明显变化时，以"【声音线索（仅供参考）】"交给 DeepSeek，并写明使用规则：只描述"怎么说的"、不代表情绪，不下情绪结论，可试探性回应并邀请确认，不说技术词，不每轮都提；督导新增 A7 检查是否误用
- 不额外调用模型；线索存在会谈记录的来访者发言里，幕后面板显示具体数字
- 局限：说话方式 ≠ 情绪（语速慢可能是难过，也可能在认真思考）；真正的情绪分类需要能听懂声音的模型，Token Plan 里暂无
- 用户决定（2026-11-02）：咨询师长期只用 DeepSeek，只升级版本号；升级前后各跑一次评测
