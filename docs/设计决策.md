# 设计决策记录

## 已定（2026-10-21）
1. 形态：Python 后端 + 本地网页；exe 以后再说。
2. 定位：实验为主——用"约束"（固定流程 + 检索 + 督导审查）模拟微调后的咨询师模型。
3. 流派：CBT 大家族——CBT + DBT + ACT；基础咨询技术、精神分析等作为补充知识。专业知识与会谈结构都按流派手册来。
4. 检索高质量咨询对话作为示范（来源见 `数据来源调研.md`）。
5. 督导审查：再调用一次模型审查回复。
6. 固定流程、固定结构。
7. 模型：千问 API。
8. 跨会谈长期记忆：要做，本地保存。
9. 与 CBT_Agent 完全独立。
10. 每轮调用次数要压缩（用户认为 3–4 次太多）。
11. （2026-10-21 修订第 3 条）放弃 DBT、ACT（没有公开范例）。候选流派改为 CBT + 精神分析/心理动力学 + 家庭系统，拉康派也查一下。
12. **范例绝不自己编写**，只用公开数据，避免污染。

13. （2026-10-21 第 4 轮）**做两个独立的咨询师，一个咨询师只用一个流派，不混用**：
    - 咨询师 A：CBT 流派（含 DBT、ACT）
    - 咨询师 B：心理动力学 + 家庭系统（谁为主待定）
    - 拉康派：只进知识库，优先级低
14. 精神分析只用来理解来访者，**不出现在主回复里，也不做解释**（此条在单咨询师方案下提出，两个咨询师方案下是否保留待确认）。
15. 长期记忆存三样：个案理解、会谈摘要、行动计划完成情况。
16. 手册检索库：我先在网上找公开资料；找不到的，用户再提供手册。
17. 用两个模型：主回复一个、督导审查一个。
18. 与 CBT_Agent（PBT 小程序）完全不同：这里不做 PBT 那种按个人过程网络选择干预。
19. 用户松口："那就编吧"——没有公开范例的 DBT/ACT/家庭系统可以生成范例（具体做法待确认）。

20. （第 5 轮）**框架和结构直接采用 PsychEval，不再自己设计**；DBT/ACT 范例按 PsychEval 的方法生成。
21. 先做咨询师 A；**咨询师 A 不保留精神分析方向**。咨询师 B 暂时不做。
22. 手册检索库多放些资料也没关系；我找到的资料不够好，需要继续找。

咨询师 A 的详细设计见 `咨询师A设计.md`。
